## Findings, most severe first

### High

**H1. First visit to the member app takes 5.7 s on 3G (target under 2 s, PRD section 15).**
Measured: first visit 5.7 s to the first paint and the usable login form, 525 KB transferred. Repeat visit 0.65 s. Admin console first visit 3.7 s.
Cause: the web export is a single-page app (`apps/member/app.json` has no `web.output`, so it defaults to `single`). `index.html` is empty, and nothing paints until `entry` (293 KB) and `__common` (214 KB) download and run. The screen is plain white until then.
Fix: (1) paint at once with an inline maroon splash in `apps/member/public/index.html`, which is also the first frame of the Phase 3 intro; (2) try `web.output: "static"` so the signed-out pages are pre-rendered; (3) split large screens out of the entry bundle. Measure again after each step.

**H2. No Landing page (S01).** `/` sends signed-out visitors straight to `/login`. The PRD (section 5, screen 1) and the `Web-Landing` / `Phone-Landing` designs want a page that explains the platform, with Sign up, Log in and the language switch. This page is where the Phase 3 animated intro lands.

### Medium

**M1. The demo login shortcut depends on one secret.** `supabase/functions/login/index.ts:105` skips the email code for `test.…@example.test` accounts when the function secret `DEMO_ACCOUNTS=1` is set. If the secret is copied to production by mistake, anyone who creates or knows such an account skips MFA. Fix: also require `platform_settings.test_data_only = true`. The database already guards that value against API changes. Add a unit test.

**M2. Signed-out pages call member-only endpoints.** On `/login` the app asks for the unread notification count and `rpc/unread_thread_count`. Both return 401 (four console errors per visit) and waste two round trips on 3G. Fix: only fetch them when a session exists.

**M3. S47 Password and sign-in is missing.** Member Settings has only privacy, alerts and data (`apps/member/app/(app)/settings/`). A signed-in member cannot change their password; they can only use Forgot password.

**M4. No forgot-password flow in the admin console.** The `Admin-Forgot`, `Admin-ForgotSent` and `Admin-NewPassword` designs exist, and A16 has the Super Administrator side ("Send reset link"). The admin login page has no "Forgot password?" link and no request page. The admin flow is still Proposed in #182, so it needs a decision first.

**M5. A09 Members is only partly built.** `/members` is the investors page (A10). There is no staff page to search all members, open one and suspend them. Suspension exists only from a report (A07).

**M6. No low-data mode.** PRD section 15 asks for a mode that hides images on mobile. Nothing in the code implements one.

**M7. The PWA has no offline shell.** `manifest.json` and icons exist, so it installs, but there is no service worker. With no signal, an installed app shows the browser's error page.

### Low

**L1. Unit tests exit 1 on Node 26.** Node 26 defines its own `globalThis.localStorage` (undefined without `--localstorage-file`), which hides jsdom's. AsyncStorage then fails in 39 member test files. CI uses Node 22 and passes. Fix: set `localStorage` from jsdom in the member test setup, or pin Node 22 in `.nvmrc` and `engines`.

**L2. Sign-in screens are plainer than the designs.** Login and sign-up are a small card on an empty cream page at 1440 px. `Web-Login` and `Main` have the photo panel (`hands-photo.jpg`) and the logo. They work at every width, but don't match the design.

**L3. Deploy access.** The Vercel CLI on this machine is signed in as `freedomselectai-6321`. The two test projects belong to the `light-8f71` team, and `.env.hosted` is not on this machine. Deploying (Phase 7) needs access to that team, or new projects.

## Checked and fine

- **RLS:** every public table has row-level security and a restrictive base rule, and `core_schema.test.sql` asserts this for any new table. Anonymous users can read only `legal_texts` and `platform_settings`.
- **Storage:** all 11 buckets are private, with size and type limits (identity documents 5 MB images only).
- **Security-definer functions** all set `search_path`.
- **Privacy rules** have their own pgTAP tests, all passing in CI: contact details, investor flag (`investor_tools`, `investor_view_minimum`), directory, member dashboard (no platform-wide counts), admin dashboard.
- **`test_data_only`** cannot be changed through the API (`guard_test_data_only` trigger).
- **Demo sign-in links** turn on only with `EXPO_PUBLIC_DEMO_LINKS=1` / `NEXT_PUBLIC_DEMO_LINKS=1`, set only on the two test Vercel projects. The hosted-only demo trust trigger is not in any migration, so a new production project never gets it.
- **Reduced motion:** `apps/member/src/components/motion.tsx` already has `useReducedMotion`, a base for Phase 3.
- **Responsive (signed out):** login, sign-up and admin login fit 375, 768 and 1440 px with no horizontal scroll.
